# MySQL 中文链上猎犬监控台设计

## 目标

把现有 Binance Futures 只读雷达改为 MySQL 存储，新增 Binance Web3 链上自动猎犬扫描，并提供一个全中文、轻量级的监控页面。

“自动打金狗”在本项目中定义为自动发现、评分、去重、保存和告警，不自动买入、不自动下单。

## 后端设计

- 使用 `mysql2/promise` 连接 `127.0.0.1:3306`，默认数据库 `crypto_monitor`、用户 `root`；密码只从本地环境变量读取。
- 保留现有 Binance USDⓈ-M Futures 采集：合约-only、5m/15m K线、OI、成交量、主动买卖和信号。
- 增加 Binance Web3 provider：通过已安装的 Binance skill CLI 获取智能钱净流入、Launchpad 生命周期和聪明钱交易信号。
- 支持 BSC、Solana、Base；对每个候选保留链、合约地址、流动性、成交量、持有人、聪明钱流入、交易地址数、风险等级、上线阶段和来源时间。
- 评分只用于观察排序：流动性、短周期成交量、聪明钱净流入、聪明钱地址数、持有人分散度、代币风险和开发者/内幕交易风险共同决定观察分数。
- provider 不可用时，API 返回数据源状态和缺失原因，不伪造“金狗”结论。

## 前端设计

- React + Vite 单页应用，开发端口 `5173`，通过 Vite 代理访问后端 `8787`。
- 深色低干扰监控台：顶部连接状态和只读标识，左侧中文导航，中间 Futures 信号和 OI/成交量图，右侧链上猎犬列表与详情。
- 所有可见文案使用中文；内部 Binance 枚举只在适配层转换为中文。
- 只展示观察、风险、证据和来源时间，不出现买入、卖出、下单或收益承诺按钮。
- 页面每 15 秒刷新，支持链筛选、信号严重度筛选和候选详情展开。

## 验收标准

1. 使用 MySQL 环境变量可完成迁移和启动，原有内存仓储测试继续通过。
2. `GET /api/onchain/gems` 返回中文页面需要的归一化猎犬候选和数据源状态。
3. 前端可在无真实链上数据时显示“数据源暂不可用”而不是空白或假数据。
4. `npm test`、`npm run build`、前端构建和浏览器页面验证通过。
